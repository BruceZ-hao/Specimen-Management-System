状态修正建议

  • 先确认现场真实状态，再手动改项目状态或工序状态。
  • 补录历史项目时，可先建立工序，再按实际进度逐项修正。
  • 人工调整后，后续业务流转仍可能继续刷新状态。

重置操作员归属

会清空项目操作员，并把进行中的工序退回待开始，适合项目被错误认领或需要换人继续处理。

重置检测员归属

会清空项目检测员和工序上的最新检测员标记，适合检测员换人或交接失败后重新分配。

已完成工序的“完成状态”不会因为重置归属而被抹掉，只会影响后续责任人和继续流转方式。

角色分配建议

  • 操作员负责认领项目、开始工序和完成工序。
  • 检测员负责在移动端上传和维护检测报告。
  • 只读账号只能看进度，不会出现处理按钮。

账号变更时的顺手检查

  • 用户停用前，先确认其当前项目是否需要转交。
  • 角色改动后，建议让对方重新登录一次移动端。
  • 密码重置后，直接通知新密码并提醒首次登录验证服务器地址。

桌面端更新

上传桌面端更新包后可直接安装，正常情况下不会覆盖本地数据库和上传文件。

服务器地址

移动端依赖公网可访问地址；地址变更后，记得重新生成并分发服务器配置二维码。

移动端版本库

上传 ZIP 更新包后自动生效，也可以从历史版本中一键回切当前分发版本。

移动端更新包要求

  • 上传 ZIP，包内固定包含 1 个 APK 和 1 个 update.json。
  • update.json 至少包含 versionName、versionCode、releaseNotes。
  • 上传成功后，新二维码和下载页会同步切到当前版本。

日常维护推荐流程

  • 创建项目并上传图纸。
  • 确认操作员和检测员账号可用。
  • 发送服务器配置二维码给现场手机。
  • 发布新 APK 后，在设置页上传 ZIP 并发送新的下载二维码。
